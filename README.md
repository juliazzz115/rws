# 📋 Учет клиентов

Веб-приложение для учета клиентов и отслеживания их статусов.

## 🚀 Как использовать

### Локальный запуск

**Вариант 1: Открыть HTML напрямую**
1. Откройте файл `index.html` в браузере
2. Введите NIP и название фирмы
3. Нажмите кнопку "Добавить"
4. Управляйте статусами в таблице

**Вариант 2: Запуск через Node.js сервер**
1. Установите зависимости: `npm install`
2. Запустите сервер: `npm start`
3. Откройте браузер по адресу: `http://localhost:3000`

### Деплой на Railway

1. Создайте аккаунт на [Railway.app](https://railway.app)
2. Подключите ваш GitHub репозиторий
3. Railway автоматически обнаружит проект и настроит деплой
4. После успешного деплоя получите публичный URL вашего приложения

**Альтернативный способ:**
```bash
# Установите Railway CLI
npm install -g @railway/cli

# Войдите в аккаунт
railway login

# Инициализируйте проект
railway init

# Задеплойте приложение
railway up
```

Railway автоматически:
- Установит зависимости (`npm install`)
- Запустит приложение (`npm start`)
- Назначит переменную окружения `PORT`
- Выдаст публичный URL

## ✨ Функции

### Ввод данных клиентов
- Поле для ввода NIP (налоговый номер)
- Поле для ввода названия фирмы (Nazwa firmy)
- Быстрое добавление клиента в таблицу

### Отслеживание статусов

**Выбор типа клиента:**
- **Подал сам** - клиент подал документы самостоятельно
- **Оплатил** - клиент оплатил услугу

**Для типа "Подал сам":**
- ✅ Проставлено в CRM - данные внесены в систему
- ✅ Проверено - информация проверена

**Для типа "Оплатил":**
- ✅ Подали - документы поданы
- ✅ Проставлено в CRM - данные внесены в систему
- ✅ Помечено - заявка помечена для обработки

### Работа с CSV файлами

**Загрузка клиентов из CSV**
- Нажмите кнопку "📂 Загрузить CSV"
- Выберите CSV файл с базой клиентов
- Клиенты автоматически добавятся в таблицу и выпадающий список

**Экспорт данных в CSV**
- Нажмите кнопку "💾 Экспортировать в CSV"
- Файл с текущими данными автоматически скачается
- Имя файла будет содержать текущую дату

### Формат CSV файла

CSV файл должен содержать следующие колонки (разделитель: запятая или точка с запятой):

```csv
NIP,Nazwa firmy,Тип,Проставлено в CRM (подал сам),Проверено,Подали (оплатил),Проставлено в CRM (оплатил),Помечено
"1234567890","ABC Company Sp. z o.o.","submitted_self",1,0,0,0,0
"2345678901","XYZ Trading","paid",0,0,1,1,1
```

**Описание колонок:**
- **NIP** - налоговый номер компании
- **Nazwa firmy** - название фирмы
- **Тип** - "submitted_self" (подал сам) или "paid" (оплатил)
- **Проставлено в CRM (подал сам)** - 1 (да) или 0 (нет)
- **Проверено** - 1 (да) или 0 (нет)
- **Подали (оплатил)** - 1 (да) или 0 (нет)
- **Проставлено в CRM (оплатил)** - 1 (да) или 0 (нет)
- **Помечено** - 1 (да) или 0 (нет)

**Примечание:** Первая строка с заголовками автоматически пропускается при загрузке. В зависимости от типа клиента используются разные наборы полей.

Пример файла доступен в `clients_example.csv`

## 💾 Сохранение данных

Все данные автоматически сохраняются в localStorage браузера. При следующем открытии приложения все клиенты и их статусы будут восстановлены.

### ⚠️ Важно: Синхронизация между устройствами

**localStorage работает только локально в браузере на конкретном устройстве.**

Это означает:
- Если вы откроете приложение с другого компьютера/телефона - вы не увидите данные с первого устройства
- Разные пользователи не могут видеть одни и те же данные
- Данные хранятся только в браузере конкретного устройства

**Для совместного использования данными между устройствами:**
- Используйте функцию "Экспортировать CSV" для сохранения данных
- Передайте CSV файл другим пользователям
- Они смогут загрузить его через "Загрузить CSV"

**Для полноценной синхронизации между устройствами потребуется:**
- Добавление серверной части (backend)
- База данных (PostgreSQL, MongoDB и др.)
- Система аутентификации пользователей
